# เพิ่มชุดตัวอักษรใน kakitori

## กติกาของโปรเจกต์นี้ (ทำตามเสมอ)

- เจ้าของโปรเจกต์**ไม่รู้ภาษาญี่ปุ่นเลย** คุณต้องรับผิดชอบความถูกต้องของเนื้อหาภาษาญี่ปุ่นเอง และบอกตรงๆ ว่าตรงไหนไม่แน่ใจ
- **ถามก่อนตัดสินใจทุกครั้ง**: เสนอตัวเลือกพร้อมคำแนะนำ แล้วรอคำตอบ ห้ามเลือกเองแม้เรื่องที่ดูเล็ก
- ตอบเป็นภาษาไทย อธิบายให้คนที่ไม่รู้ภาษาญี่ปุ่นเข้าใจ
- ห้าม commit หรือ push เอง ให้ถามก่อน และเช็ค branch ปัจจุบันก่อนทุกครั้ง (`main` = เว็บจริงบน Vercel)

## 1. ตกลงกับเจ้าของก่อนแก้โค้ด

ถามเรื่องเหล่านี้ (ใช้ AskUserQuestion ได้ครั้งละไม่เกิน 4 ข้อ):

- **รูปแบบ:** เป็นชุดใหม่ที่มีเมนูและ URL ของตัวเอง (เช่น `/kanji`) หรือเพิ่มแถวในชุดเดิม
  (เช่น ตัวควบ きゃ ใส่ทั้งฮิรางานะและคาตาคานะ — `GroupKind` มี `'yoon'` เตรียมไว้แล้ว)
- **ขอบเขต:** ตัวไหนบ้าง กี่ตัว เรียงลำดับอย่างไร
- **การฝึกเขียน:** ตัวควบ/ตัวเล็กให้ฝึกเขียนแบบไหน (ทีละตัว หรือเขียนทั้งคู่)
- **เนื้อหา:** ต้องมีคำอ่านไทย หมายเหตุ ตัวที่หน้าคล้ายกัน และคำตัวอย่างไหม
- **เส้นทาง "เรียนต่อ":** ชุด/แถวใหม่อยู่ลำดับไหน (ลำดับตาม `scriptList` และ `groups`)
- **ความคืบหน้าเดิมของผู้ใช้:** id ตัวอักษรเป็น key ใน localStorage และในไฟล์สำรอง — **ห้ามเปลี่ยน id เดิม**

## 2. ขั้นตอนและไฟล์ที่ต้องแก้

1. **ข้อมูลลำดับขีด** — เพิ่มตัวอักษรใน `SETS` ของ `scripts/fetch-kanjivg.mjs` แล้วสร้าง JSON
   โดยล็อก KanjiVG ให้เป็นเวอร์ชันเดียวกับชุดเดิม (ดูค่า `ref` ใน `src/data/strokes/hiragana.json`):
   ```powershell
   $env:KANJIVG_REF = '<ref จากไฟล์เดิม>'; npm run data:strokes -- <ชื่อชุด>
   ```
   ได้ไฟล์ `src/data/strokes/<ชื่อชุด>.json` (สัญญาอนุญาต CC BY-SA 3.0 เหมือนชุดเดิม)
2. **ข้อมูลตัวอักษร** — สร้าง `src/data/scripts/<ชื่อชุด>.ts`
   - ชุดคานะ: ใช้ `buildKana` / `kanaGroups` / `KANA_SOUNDS` ใน `kanaShared.ts` (ดู `katakana.ts` เป็นตัวอย่าง)
   - ชุดอื่น: สร้าง `CharEntry[]` เองตาม `src/data/types.ts`
   - id ไม่ซ้ำในชุด, `col` 0–4, ตัวใน `similar` และ `base` ต้องมีอยู่ในชุดเดียวกัน
   - คำตัวอย่างแยกไว้ไฟล์ `<ชื่อชุด>Words.ts` ให้ตรวจง่าย
3. **ลงทะเบียน** — เพิ่มชื่อใน `ScriptId` (`src/data/types.ts`) และใน `scripts` ของ `src/data/scripts/index.ts`
   (ลำดับใน `scripts` = ลำดับในเมนูและในเส้นทาง "เรียนต่อ") ถ้าเสียงตรงกับชุดอื่นทีละตัว ให้ตั้ง `counterpart`
4. **เทส** — `src/data/data.test.ts` ตรวจทุกชุดใน `scriptList` อัตโนมัติ (id ไม่ซ้ำ, อ้างอิงถูก, มีลำดับขีดครบ)
   แต่ต้องเพิ่มเองสำหรับ: จำนวนขีดมาตรฐาน (`STANDARD_STROKES`) จำนวนตัวในชุด และกติกาคำตัวอย่าง
   ถ้าเทสตัวตรวจลายมือต้องใช้ชุดใหม่ ให้เพิ่มใน `src/features/writing/engine/testUtils.ts`
5. **ข้อความที่เขียนชื่อชุดไว้ตรงๆ** (ไม่อัปเดตเอง):
   `index.html` (title, description), `vite.config.ts` (ชื่อแอป PWA), `src/pages/HomePage.tsx` (FEATURES),
   `src/pages/StartPage.tsx`, `README.md`
6. **ฟอนต์** — `src/styles/fonts.css` โหลด Klee One เฉพาะชุดย่อยคานะ ตัวเล็ก/ตัวควบใช้ได้เลย
   แต่คันจิต้องเปลี่ยนเป็นฟอนต์ชุดเต็ม และควรโหลดข้อมูลลำดับขีดทีละตัวแทนทั้งชุด (ดู README)
7. **หน้าจอ** — ชุดใหม่จะขึ้นในหน้าหมวดตัวอักษร (`/kana`, `src/pages/KanaHubPage.tsx`) และเส้นทางบนหัวเว็บเอง
   (URL สร้างผ่าน `scriptPath()` ใน `src/app/paths.ts`) — ตรวจว่ารายการและเส้นทางยังพอดีบนมือถือกว้าง 390px
   ถ้าเป็นหมวดใหม่ (ไม่ใช่ชุดตัวอักษร) ให้เพิ่มใน `src/app/sections.ts` และ `MAIN_NAV` ใน `src/app/AppLayout.tsx`

## 3. กติกาเนื้อหาภาษาญี่ปุ่น

- **โรมาจิ:** Hepburn ถ้ามีแบบอื่นที่ถือว่าถูกด้วยใส่ `romajiAlt` (เช่น を = wo / o)
- **คำอ่านไทย:** เสียงโดยประมาณ ใช้แบบเดียวกับ `KANA_SOUNDS` (เช่น つ = ทสึ, ん = อึน)
- **คำตัวอย่าง:** 1 คำต่อตัว เป็นคำพื้นฐาน ใช้เฉพาะตัวที่สอนแล้ว (มีเทสตรวจ)
  ใส่คันจิเฉพาะคำที่ปกติเขียนด้วยคันจิ โรมาจิสะกดตามคานะ (おう = ou, ー = สระซ้ำ)
  คำทับศัพท์ใส่ `origin` (คำต้นทาง)
- ตรงไหนไม่แน่ใจ ให้จดไว้และบอกเจ้าของ จุดเหล่านี้ต้องให้ผู้รู้ภาษาญี่ปุ่นช่วยตรวจ

## 4. ตรวจก่อนส่งงาน

1. `npx tsc -b` → `npx eslint .` → `npm test` → `npm run build` ต้องผ่านทั้งหมด
2. ลองในเบราว์เซอร์จริง: ตารางตัวอักษร, คัดตัวอักษรทั้ง 4 โหมด, แบบทดสอบ, ทบทวน, พิมพ์แบบฝึก,
   สลับชุด และหน้าจอมือถือ 390px ทั้งธีมสว่างและธีมมืด
3. ใช้ `/kakitori-content-review` เพื่ออัปเดตตารางให้ผู้รู้ภาษาญี่ปุ่นช่วยตรวจ
4. สรุปเป็นภาษาไทย: ทำอะไรไปบ้าง ไฟล์ไหน ตรงไหนไม่แน่ใจ แล้วถามว่าจะ commit อย่างไร
