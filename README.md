# kakitori 書き取り

เว็บฝึกคัดตัวอักษรญี่ปุ่นทีละขีด — ชื่อมาจาก 書き取り (kakitori) แปลว่าแบบฝึกคัดเขียนตัวอักษร
มี **ฮิรางานะ** (108 ตัว) และ **คาตาคานะ** (109 ตัว) — สลับชุดได้จากปุ่ม ひらがな / カタカナ ด้านบน
แต่ละชุดแบ่งเป็น 2 ระดับ (มีแท็บในตาราง แบบทดสอบ และพิมพ์แบบฝึก):

- **ระดับ 1 ตัวพื้นฐาน** — 46 ตัว + ตัวขุ่น/ครึ่งขุ่น 25 ตัว
- **ระดับ 2 ตัวเล็กและตัวควบ** — ตัวเล็ก ゃ ゅ ょ っ (คาตาคานะมี ー เพิ่ม) + ตัวควบ 33 ตัว (きゃ …)
  ตัวควบไม่มีลำดับขีดของตัวเอง จึงฝึกอ่าน/ฟัง/ทำแบบทดสอบ ส่วนการเขียนฝึกจากตัวที่ประกอบกัน (ตัวใหญ่ + ตัวเล็ก)

เส้นทาง "เรียนต่อ": ฮิรางานะ ระดับ 1 → คาตาคานะ ระดับ 1 → ฮิรางานะ ระดับ 2 → คาตาคานะ ระดับ 2

- เข้าใช้ได้ทันที ไม่ต้อง login
- ไม่มี server และไม่มี database — ความคืบหน้าเก็บใน `localStorage` ของเบราว์เซอร์ผู้ใช้เท่านั้น
- ติดตั้งเป็นแอป (PWA) และใช้ออฟไลน์ได้

## ฟีเจอร์

| เมนู | รายละเอียด |
| --- | --- |
| เริ่มต้นที่นี่ (`/start`) | พื้นฐานสำหรับคนไม่รู้ภาษาญี่ปุ่น: ตัวอักษร 3 แบบ, อ่านตาราง, ตัวขุ่น, ลำดับขีด, เสียงยาว ー, วิธีเรียน — มีแถบชวนอ่านเมื่อเข้าเว็บครั้งแรก |
| เรียนต่อ | การ์ดบอกขั้นถัดไปตามลำดับ ฮิรางานะ → คาตาคานะ ทีละแถว (ผ่านแถว = เขียนครบทุกตัว + ตอบถูกตัวละ 1 ครั้ง) |
| คัดตัวอักษร | 4 โหมด: **ดูลำดับขีด** (แอนิเมชัน/ทีละขีด) → **เขียนทับ** (มีเส้นจาง + ตรวจทีละขีด) → **ตรวจทีละขีด** (ไม่มีเส้นนำ) → **เขียนอิสระ** (เขียนทั้งตัวแล้วให้คะแนนรายขีด) |
| แบบทดสอบ | ดูตัว→เลือกคำอ่าน, ดูคำอ่าน→เลือกตัว, ฟังเสียง→เลือกตัว, ดูคำอ่าน→เขียนตัว, จับคู่ฮิรางานะ↔คาตาคานะ (เช่น あ→ア) |
| ทบทวน | ตัวที่ถึงรอบทบทวนวันนี้ (นัดห่างขึ้นเรื่อยๆ ตามระบบกล่องแบบ Leitner) ตัวที่ผิดบ่อย สรุปความคืบหน้า และสำรอง/นำเข้าไฟล์ |
| พิมพ์แบบฝึก | สร้างกระดาษคัดลายมือ A4 (ตัวต้นแบบ + ลำดับขีด + ช่องเขียนทับ) พิมพ์หรือบันทึก PDF |

หน้าคัดตัวอักษรมีคำศัพท์ตัวอย่างตัวละ 1 คำ (พร้อมคันจิ หรือคำต้นทางของคำทับศัพท์) และตารางตัวอักษรมีคำอธิบายแต่ละหมวด

> ⚠️ เนื้อหาภาษาญี่ปุ่นที่เขียนเอง (คำอ่านไทย หมายเหตุ คำศัพท์ตัวอย่าง หน้าเริ่มต้นที่นี่) ยังไม่ได้ให้ผู้รู้ภาษาญี่ปุ่นตรวจ
> ควรตรวจก่อนเปิดให้คนทั่วไปใช้ — ไฟล์ที่เกี่ยวข้อง: `src/data/scripts/*.ts`, `src/pages/StartPage.tsx`

อื่นๆ: โหมดมืด, เสียงอ่าน (Web Speech API — ซ่อนอัตโนมัติถ้าเครื่องไม่มีเสียงญี่ปุ่น), ใช้ได้ทั้งนิ้ว ปากกา และเมาส์

## เริ่มใช้งาน

ต้องใช้ **Node.js 22.22 ขึ้นไป** (โปรเจคนี้พัฒนาบน Node 24 LTS)

```bash
npm install
npm run dev        # เปิดเว็บสำหรับพัฒนา http://localhost:5173
npm test           # รันเทส (ตัวตรวจลายมือ, แบบทดสอบ, ข้อมูล)
npm run lint       # ตรวจโค้ด
npm run build      # build เป็นไฟล์ static ไว้ที่ dist/
npm run preview    # ดูผล build จริง (รวม PWA) http://localhost:4173
```

คำสั่งที่ใช้นานๆ ครั้ง:

```bash
npm run data:strokes   # ดึงข้อมูลลำดับขีดจาก KanjiVG ใหม่ → src/data/strokes/*.json
npm run icons          # สร้างไอคอน PWA ใหม่จาก public/logo.svg
```

## โครงสร้างโปรเจค

```
src/
├─ data/                      ข้อมูลตัวอักษร (ไม่ผูกกับหน้าจอ)
│  ├─ types.ts                โครงสร้าง ScriptPack / CharEntry / StrokeData
│  ├─ scripts/kanaShared.ts   ตารางเสียงที่คานะทั้งสองชุดใช้ร่วมกัน (โรมาจิ คำอ่านไทย แถว)
│  ├─ scripts/hiragana.ts     ฮิรางานะ: ตัวอักษร ตัวที่หน้าคล้ายกัน หมายเหตุ
│  ├─ scripts/katakana.ts     คาตาคานะ: ตัวอักษร ตัวที่หน้าคล้ายกัน หมายเหตุ
│  ├─ scripts/*Words.ts       คำศัพท์ตัวอย่างของแต่ละชุด (แยกไฟล์ให้ตรวจง่าย)
│  ├─ scripts/index.ts        ทะเบียนชุดตัวอักษร
│  └─ strokes/*.json          ข้อมูลลำดับขีด (สร้างจาก KanjiVG)
├─ features/
│  ├─ writing/engine/         ตัวตรวจลายมือ (pure functions + เทส)
│  ├─ writing/*.tsx           กระดานเขียน แอนิเมชัน กระดานตรวจ
│  ├─ quiz/                   สร้างคำถาม/ตัวหลอก และหน้าจอแบบทดสอบ
│  ├─ progress/               ความคืบหน้า (localStorage) และเส้นทาง "เรียนต่อ" (learningPath.ts)
│  ├─ settings/               การตั้งค่า (localStorage)
│  └─ speech/                 เสียงอ่าน
├─ pages/                     หน้าต่างๆ (ทุกหน้าใต้ /:script ใช้ได้กับทุกชุดตัวอักษร)
└─ app/                       layout, router, ธีม, PWA
```

โครงเมนูเป็นหน้าศูนย์รวมทีละชั้น (หน้าแรก › หมวด › ชุด › เมนูย่อย) หัวเว็บแสดงเส้นทาง — URL สร้างผ่าน `src/app/paths.ts`

URL: `/` (เลือกหมวด) → `/kana` (หมวดตัวอักษร) → `/kana/hiragana` (ตาราง + เมนูย่อย) →
`/kana/hiragana/practice/ka?mode=trace`, `/kana/hiragana/quiz`, `/kana/hiragana/review`, `/kana/hiragana/worksheet` ·
`/review` (ทบทวนรวม) · `/start` (บทเรียนพื้นฐาน) — URL เดิม (`/hiragana/...`) ส่งต่อมาที่ `/kana/hiragana/...` ให้อัตโนมัติ
· `/n5` (หมวด JLPT N5) → `/n5/vocab` (สายคำศัพท์) → `/n5/vocab/family?step=practice` (บทเรียน: เรียน / ฝึก / ทดสอบ)
· `/n5/vocab/review` (ทบทวนคำศัพท์: คำที่ถึงรอบ · คำที่ผิดบ่อย — `?start=due` เริ่มทบทวนทันที)
หมวดใหม่ (ท่องเที่ยว ฯลฯ) เพิ่มใน `src/app/sections.ts` และเมนูหลักใน `MAIN_NAV` ของ `src/app/AppLayout.tsx`

คำศัพท์อยู่ที่ `src/data/vocab/` — ชุดคำ → ช่วง (区間) → บท (สถานี) → คำ เช่น N5 แยกไฟล์ละช่วงใน `n5/*.ts`
(เขียนด้วยตัวช่วย `w()` ใน `build.ts` · โรมาจิสร้างจากคานะอัตโนมัติด้วย `romaji.ts`)
**id ของคำและบทห้ามเปลี่ยน** (เป็น key ของความคืบหน้า) และเปิดช่วงใหม่ต่อท้ายเสมอ (เลขสถานีจะได้ไม่เลื่อน)
คำศัพท์ N5 ครบแล้ว (13 ช่วง 87 บท 673 คำ) — ที่มา การแบ่งช่วง และคำที่รวมการ์ด: `docs/n5-vocab-plan.md`
ความคืบหน้ารายคำเก็บใน `localStorage` ร่วมกับตัวอักษร (`ProgressData.scripts['vocab-n5']`) จึงติดไปกับไฟล์สำรองด้วย
(เปลี่ยน `hiragana` เป็น `katakana` ได้ทุกหน้า — ฮิรางานะและคาตาคานะใช้ id ตัวอักษรเดียวกัน เช่น `ka` = か / カ)

### ตัวตรวจลายมือทำงานอย่างไร

พิกัดทั้งหมดอยู่ในกรอบ 109×109 ตาม KanjiVG ระบบจะสุ่มจุดของเส้นที่ผู้ใช้เขียนและเส้นต้นแบบให้มีจำนวนเท่ากัน
แล้ววัดระยะเฉลี่ยแบบจุดต่อจุด (บอกตำแหน่ง+รูปร่าง+ทิศทาง) วัดแบบกลับหัวเส้น (จับการเขียนผิดทิศ)
และวัดความคล้ายของทิศทางรายช่วง ถ้าไม่ตรงขีดที่ต้องเขียน จะลองเทียบกับขีดถัดๆ ไปเพื่อบอกว่า “ผิดลำดับ”
โหมดที่ไม่มีเส้นนำจะชดเชยตำแหน่งอัตโนมัติ (เขียนเยื้องทั้งตัวได้) ส่วนโหมดเขียนอิสระจะปรับขนาดลายมือให้เท่าต้นแบบก่อนให้คะแนน
ความเข้มงวด (ง่าย/ปกติ/เข้ม) ปรับได้ในหน้าคัดตัวอักษร

## การเพิ่มชุดตัวอักษรใหม่

(คาตาคานะเพิ่มด้วยขั้นตอนนี้ — ใช้ `katakana.ts` เป็นตัวอย่างได้)

1. เพิ่มรายการตัวอักษรใน `SETS` ของ `scripts/fetch-kanjivg.mjs` แล้วรัน `npm run data:strokes -- <ชื่อชุด>`
   (ตั้ง `KANJIVG_REF` ให้ตรงกับค่า `ref` ในไฟล์ JSON เดิม เพื่อให้ทุกชุดมาจาก KanjiVG เวอร์ชันเดียวกัน)
2. สร้าง `src/data/scripts/<ชื่อชุด>.ts`
3. เพิ่มชื่อชุดใน `ScriptId` (`src/data/types.ts`) และลงทะเบียนใน `src/data/scripts/index.ts`
4. รัน `npm test` — เทสจะตรวจให้ว่าทุกตัวมีข้อมูลลำดับขีด และข้อมูลอ้างอิงกันถูกต้อง

หน้าทั้งหมด (คัด/ทดสอบ/ทบทวน/พิมพ์) จะใช้งานได้ที่ `/<ชื่อชุด>/...` ทันที และปุ่มสลับชุดด้านบนจะมีชุดใหม่เพิ่มเอง
ถ้าชุดใหม่มีเสียงตรงกับชุดอื่นทีละตัว ให้ตั้ง `counterpart` เพื่อเปิดข้อสอบแบบจับคู่
(ถ้าจะทำคันจิ ให้เปลี่ยนไปใช้ฟอนต์ชุดเต็มตามคำอธิบายใน `src/styles/fonts.css` และควรโหลดข้อมูลลำดับขีดทีละตัวแทนทั้งชุด)

## ข้อมูลที่เก็บในเบราว์เซอร์

| key | ข้อมูล |
| --- | --- |
| `jp-learn:settings:v1` | ธีม ความเข้มงวด ความเร็วแอนิเมชัน ค่าแบบทดสอบล่าสุด เป้ารายวัน |
| `jp-learn:progress:v1` | สถิติรายตัว (กล่องทบทวน ถูก/ผิด คะแนนเขียนอิสระสูงสุด เวลาตอบล่าสุดสำหรับนัดทบทวน) |
| `jp-learn:activity:v1` | จำนวนครั้งที่ฝึกในแต่ละวัน และวันที่ถึงเป้า (ใช้นับวันฝึกต่อเนื่อง) |

ผู้ใช้สำรอง/นำเข้าข้อมูล `progress` + `activity` เป็นไฟล์ JSON ได้ที่หน้า “ทบทวน” (`src/features/progress/backup.ts`)
— นำเข้าแบบรวมข้อมูล ตัวไหนมีทั้งสองฝั่งใช้ฝั่งที่ฝึกล่าสุด

**กติการอบทบทวน** (`src/features/progress/progressLogic.ts`): ตอบถูกเลื่อนขึ้น 1 กล่อง (เลื่อนได้วันละครั้ง) ตอบผิดกลับกล่อง 0
นัดทบทวนครั้งถัดไปตามกล่อง 0 / 1 / 2 / 4 / 7 / 14 วันนับจากวันที่ตอบล่าสุด

## การนำขึ้นเว็บ (deploy) — Vercel

ตั้งค่าไว้แล้วใน `vercel.json` (build ด้วย `npm run build`, ส่งออกที่ `dist/`, ทุก path ส่ง `index.html` กลับมา
เพื่อให้ URL อย่าง `/hiragana/quiz` เปิดตรงได้) และ `package.json` ระบุ Node 24

ตั้งค่าครั้งแรก (ทำครั้งเดียว ผ่านหน้าเว็บ Vercel):

1. ไปที่ <https://vercel.com> → สมัคร/เข้าสู่ระบบด้วยบัญชี GitHub
2. **Add New… → Project** → เลือก repo `kakitori` (ถ้าไม่เห็น กด “Adjust GitHub App Permissions” แล้วอนุญาต repo นี้)
3. หน้าตั้งค่าไม่ต้องแก้อะไร (Framework: Vite ตรวจเจอเอง) → กด **Deploy**
4. ได้ลิงก์เว็บ เช่น `https://kakitori.vercel.app` (ถ้าชื่อนี้ถูกใช้แล้ว Vercel จะตั้งชื่ออื่นให้ เปลี่ยนได้ใน Settings → Domains)

หลังจากนั้นทุกครั้งที่ push:

- push เข้า **production branch** (ค่าเริ่มต้นคือ `main`) → อัปเดตเว็บจริง
- push เข้า branch อื่น (เช่น `dev`) → ได้ลิงก์ **Preview** แยกไว้ลองก่อน ไม่กระทบเว็บจริง

เปลี่ยน production branch ได้ที่ Settings → Git → Production Branch

หลัง deploy ให้ทดสอบตาม [docs/device-test-checklist.md](docs/device-test-checklist.md)
